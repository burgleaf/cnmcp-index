# 资源质量评分与排序

正式目录默认按开源项目本身的综合质量排序，不使用本站 `createdAt`（收录日期），也不因支持平台更多、标签更多或站内点击更多而加分。

## 第一版公式

总分为 100 分，构建时从资源事实计算：

- GitHub Stars：40 分。使用对数缩放，10 万 Stars 达到该项上限，避免头部项目完全垄断。
- 上游活跃度：25 分。最近推送在 30、90、180、365、730 天内依次获得 25、20、15、10、5 分，更早仍保留 1 分。
- GitHub Forks：10 分。使用对数缩放，1 万 Forks 达到该项上限。
- 资料完整度：15 分。按官方文档、本地审核 README、许可证、图片和平台支持说明计算。
- 编辑精选：10 分。只由维护者审核决定。

归档仓库的最终得分乘以 0.25。最终同分依次比较上游最近推送时间、规范化名称和资源 ID，保证结果稳定。

## 维护状态与数据更新时间

Catalog 会随质量快照生成维护状态：已归档仓库标为“已归档”；未归档且最近推送距快照不超过 180 天标为“活跃”；其余或缺少可验证推送记录的资源标为“低活跃”。“数据更新时间”是最近一次获取 GitHub 仓库事实的日期，不是本站收录日期。它是维护线索，不代表安全审计或功能可用性保证。

## 数据治理

`sourceStats` 保存 Stars、Forks、最近推送时间、归档状态和抓取日期。维护者使用 `yarn sync:github-metadata` 从公开 GitHub 仓库同步；投稿者不应自行填写或修改这些值。所有 `resources/**` 变更都需要当前提交上的维护者批准。

评分只是发现线索，不代表安全审计或适合所有场景。平台支持仅在详情页按上游证据说明，不参与排序。
